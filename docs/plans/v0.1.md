# Implementation Plan

## Milestone 1: Durable core

1. Add canonical envelope and digest functions.
2. Add SQLite schema and migrations.
3. Add the request state machine.
4. Add one-use claim and crash recovery.
5. Add redacted display and replay projections.

Proof: unit tests plus concurrent claim and restart tests.

## Milestone 2: Hermes runtime integration

1. Register `pre_tool_call` and `post_tool_call` hooks.
2. Register `tool_execution` middleware.
3. Add explicit policy configuration and a deterministic demo effect.
4. Add structured pending, denied, and completion results.
5. Add plugin doctor and CLI inspection commands.

Proof: Hermes loader tests and `hermes plugins doctor . --ci`.

## Milestone 3: Decision API and session continuation

1. Add namespaced FastAPI routes for list, detail, approve, deny, comment, cancel, and retry resume.
2. Store the originating profile and session lineage.
3. Add Desktop calls to open or resume the stored session.
4. Submit hidden decision prompts with `display_kind: "hidden"`.
5. Track resume delivery and failure.

Proof: API tests with a fake session transport and gateway contract tests.

## Milestone 4: Desktop inbox

1. Add sidebar route and pending badge.
2. Render exact metadata, arguments approved for display, audit history, and status.
3. Add approve, deny, comment, cancel, and retry-resume actions.
4. Add loading, empty, stale, conflict, and disconnected states.
5. Add accessible keyboard and screen-reader labels.

Proof: component tests and local Desktop E2E.

## Milestone 5: Publication adapter

1. Add generic publish envelope fields.
2. Add a mock publisher with idempotency and uncertain-outcome fixtures.
3. Add an X adapter behind explicit configuration.
4. Provide deployment guidance that removes raw write alternatives.
5. Keep all live provider tests opt-in.

Proof: mock end-to-end flow. A live X smoke requires a separate exact owner approval.

## Milestone 6: Release

1. Run Python, lint, type, plugin doctor, Desktop, and security suites.
2. Run an independent exact-tree review.
3. Document installation, policy configuration, and security limits.
4. Tag only after clean-checkout verification.
